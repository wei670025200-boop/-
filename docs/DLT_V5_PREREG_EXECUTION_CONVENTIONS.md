# DLT cleanroom execution conventions (pre-data, implementation decisions)

- To operationalize the Phase 3 cutoff without looking at outcomes, freeze the reference at the first 100 Phase 3 OOS rows (the existing inner_warmup). Reference uses population standard deviation floored at 1e-6. CUSUM starts at zero after that cutoff and checks the latest 20 trajectory values.
- The candidate grid is evaluated in the common ticket-count domain 1..18 (reference N=18; all candidates unchanged in that range). No admission for N>18 follows from this one-shot test. The existing effective K expansion primitive remains available; policy use for a different domain requires separately authorized validation, not a rerun.
- Front rank is the 1-based ascending model-score rank / number of eligible combinations after the five exclusion masks; exact enumeration of all 324632 candidates. Excluded outcomes cannot be hits. Ties use lexicographic order. Back rank is 1..66 by ascending predicted score with lexicographic ties. All fits use strictly earlier rows. Inner selection is on the expanding prior OOS trace, warmup=100; ties use fixed grid order; when no candidate qualifies, that outer row is a no-hit for both zones, not silently removed. Resample validity requires the same outer minimum hits in the bootstrap replicate; sparse capture lift is nominal diagnostic only.
- The prereg_spec_sha256 binds a canonical JSON object with the SHA-256 of the original spec, final user addendum and this execution conventions file. No change after reading real data. Combined bootstrap seed 2026112503; policy seed 2026112504. Canonical JSON uses sorted keys, UTF-8, compact separators, no NaN.
- The transaction implementation uses a POSIX local filesystem supporting flock/fsync/atomic rename. A logically append-only ledger is updated by atomic replacement with the verified old bytes plus exactly one entry. Dry-run is isolated and never writes production records; it does not authorize a ticket purchase. Phase 4 stays LOCKED. No external timestamp/witness or filesystem rollback protection is claimed.
